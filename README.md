# Shivrajsinh Zala — Frontend Developer Portfolio

This is the repository for the personal developer portfolio, blog, and online resume of **Shivrajsinh Zala**, based in Rajkot, Gujarat. The website is styled in a custom, premium, high-contrast **Brutalist Web Design** aesthetic, incorporating tactile mouse-tilt interactions, smooth scroll mechanics, and micro-animations.

---

## 🚀 Key Features

* **Brutalist Design System**: Built with strict high-contrast borders, solid shadows (`brutal-shadow`), curated neon/pastel accents (pink, cyan, yellow, purple), and graph-paper backdrop coordinates.
* **Online Resume (`/resume`)**: A professional overview page presenting work history, MCA/BCA education, and skill level charts.
* **Optimized PDF CV**: Includes a one-click PDF download pointing to a clean, standard CV file (`/assets/resume-shivrajsinh-zala.pdf`). Generated via headless browser print layouts to ensure it has no web elements (nav/footer) and is 100% **ATS-friendly** (optimized down to a lean **134 KB**).
* **Interactive CLI Terminal (`_TERMINAL`)**: An in-browser developer console mockup allowing command-line navigation (`about`, `projects`, `skills`, `clear`, `neofetch`, `secrets`).
* **Interactive Contact Form (`/contact`)**: Form inquiries integrated asynchronously with **Web3Forms** featuring custom GSAP modal states ("TRANSMITTING", "SUCCESS") and field shake validation.
* **A11y & SEO Compliance**: High-contrast ratios to satisfy WCAG AA standards, structured breadcrumbs schema JSON-LD, self-referencing canonical links, and automated sitemap compilation.

## 🛠️ Tech Stack

* **Framework**: [Astro v6](https://astro.build/) (Static Site Generation)
* **Styling**: [Tailwind CSS v4](https://tailwindcss.com/) (using Vite compilation directives and `@theme` custom HSL bindings)
* **Components**: React.js
* **Animations**: GSAP (GreenSock Animation Platform) & ScrollTrigger
* **Smooth Scrolling**: Lenis
* **Icons**: Lucide Icons
* **Hosting**: GitHub Pages

## 💻 Developer Commands

All commands are run from the project root directory:

| Command | Action |
| :--- | :--- |
| `npm install` | Installs project dependencies |
| `npm run dev` | Starts local development server at `http://localhost:4321` |
| `npm run build` | Builds optimized static production bundle in `/dist/` |
| `npm run preview` | Previews the compiled `/dist/` output locally |
| `npm run blog:list` | Shows the editorial queue — what's published, what's next |
| `npm run blog:dry` | Generates the next article and prints it without writing a file |
| `npm run blog:generate` | Generates the next article and writes it to `src/content/blog/` |

## 🤖 Auto Blog Deployer

A weekly article is generated by Groq and committed automatically. Cloudflare Pages picks
up the push and deploys.

### How it works

```text
.github/workflows/auto-blog.yml   Tuesdays 04:00 UTC (09:30 IST), or run manually
   └─ scripts/generate-blog.mjs
        ├─ picks the first unpublished topic from scripts/topics.mjs
        ├─ Pass 1 → Groq: editorial brief (title, meta, outline, 5 FAQs) as JSON
        ├─ Pass 2 → Groq: full markdown draft against that outline
        ├─ validates: word count, banned AI phrases, internal links, no H1, no placeholders
        ├─ up to 2 repair passes if validation fails
        └─ writes src/content/blog/<slug>.md
   └─ npm run build   (a broken post never reaches production)
   └─ git commit + push
```

If the draft still fails validation after two repair passes, the run **fails and publishes
nothing**. Silence is better than a bad post on your domain.

### Setup

1. Get a free API key at [console.groq.com/keys](https://console.groq.com/keys).
2. Add it to this repo: **Settings → Secrets and variables → Actions → New repository secret**
   * Name: `GROQ_API_KEY`
   * Value: your key
3. Optional: add a repository **variable** `GROQ_MODEL` to override the default
   (`llama-3.3-70b-versatile`).

That's the whole setup. The schedule starts on the next Tuesday.

### Running it manually

* **GitHub**: Actions → *Auto blog* → *Run workflow*. Optionally force a topic slug, or
  tick *dry run* to generate without committing.
* **Locally**: `GROQ_API_KEY=xxx npm run blog:dry` to preview, `npm run blog:generate` to write.

### Managing the editorial queue

`scripts/topics.mjs` is the publishing calendar — the generator walks it top to bottom and
publishes the first topic whose slug isn't already in `src/content/blog/`. When it runs out,
the workflow exits cleanly and tells you to add more.

Each topic is a **brief**, not a title. The `angle` and `mustCover` fields are what keep
output specific instead of generic — a vague brief produces a vague article, so keep them
concrete. The model writes the title itself.

### Editing or removing a post

Posts are plain markdown in `src/content/blog/`. Edit the file, or delete it to unpublish.
Set `draft: true` in the frontmatter to hide a post from the index and from search without
deleting it. Every generated post carries a `generatedBy` field so machine drafts can be
audited later.

## 🔎 SEO Structure

* **Local service pages** — `/wordpress-developer-rajkot`, `/squarespace-developer-rajkot`,
  `/wordpress-developer-morbi`, `/squarespace-developer-morbi`, hubbed at `/services`.
  Content lives in `src/data/services.ts`; all four render through
  `src/components/ServicePage.astro`. Each carries `ProfessionalService` + `BreadcrumbList`
  + `FAQPage` schema with `areaServed`.
* **Entity schema** — the homepage `@graph` carries `Person` (with `hasOccupation`,
  `makesOffer`, `alternateName`), `ProfilePage`, `WebSite` and a six-question `FAQPage`,
  all cross-referenced by `@id` so Google resolves them as one entity.
* **Sitemap** — generated by `@astrojs/sitemap`, filtered to exclude `noindex` pages
  (`/resume-pdf`, `/janki`) so the sitemap never contradicts the robots meta.
